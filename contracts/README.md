# Vanguard Contracts

Soroban smart contracts for Vanguard's Blindside ZK tactical game.

## Overview

This directory contains two contracts that work together to create a playable 1v1 ZK game:

1. **vanguard_verifier** - UltraHonk proof verification contract
2. **vanguard_hub** - Game logic and state management contract

## Contracts

### vanguard_verifier

**Purpose:** Verify UltraHonk ZK proofs generated by Noir circuits.

**Features:**
- ✅ Wraps official Noir UltraHonk verifier
- ✅ Embedded verification key
- ✅ Returns boolean (valid/invalid)
- ✅ Minimal gas footprint
- ✅ No game logic

**Documentation:** [vanguard_verifier/README.md](./vanguard_verifier/README.md)

### vanguard_hub

**Purpose:** Manage game state, enforce rules, coordinate proof verification.

**Features:**
- ✅ Game state management
- ✅ Turn order enforcement
- ✅ Commitment storage and validation
- ✅ HP tracking and win conditions
- ✅ Replay attack prevention
- ✅ Event emission
- ✅ ZK proof integration

**Documentation:** [vanguard_hub/README.md](./vanguard_hub/README.md)

## Deployment Order

1. **Deploy Verifier Contract First**
   ```bash
   cd vanguard_verifier
   make build && make optimize
   make deploy
   ```

2. **Configure Verifier Address in Hub**
   ```bash
   cd vanguard_hub
   # Update VERIFIER_CONTRACT_ID constant or add set_verifier()
   make build && make optimize
   make deploy
   ```

3. **Initialize Game**
   ```bash
   soroban contract invoke \
     --id $HUB_CONTRACT_ID \
     --network standalone \
     -- \
     initialize_game \
     --p1 $P1_ADDRESS \
     --p2 $P2_ADDRESS
   ```

## Quick Start

### 1. Install Dependencies

```bash
# Install Rust and Soroban
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup target add wasm32-unknown-unknown

# Install Soroban CLI
cargo install soroban-cli
```

### 2. Build Contracts

```bash
cd contracts

# Build both contracts
make -C vanguard_verifier build
make -C vanguard_hub build
```

### 3. Deploy to Standalone Network

```bash
# Start local network
soroban network standalone

# Deploy verifier
VERIFIER_ID=$(soroban contract deploy \
  --wasm vanguard_verifier/target/wasm32-unknown-unknown/release/vanguard_verifier.optimized.wasm \
  --network standalone)

# Deploy hub (with verifier configured)
HUB_ID=$(soroban contract deploy \
  --wasm vanguard_hub/target/wasm32-unknown-unknown/release/vanguard_hub.optimized.wasm \
  --network standalone)

echo "Verifier: $VERIFIER_ID"
echo "Hub: $HUB_ID"
```

### 4. Initialize Game

```bash
# Get addresses (from Soroban standalone setup)
P1_ADDRESS=GD...
P2_ADDRESS=GB...

# Initialize game
soroban contract invoke \
  --id $HUB_ID \
  --network standalone \
  -- \
  initialize_game \
  --p1 $P1_ADDRESS \
  --p2 $P2_ADDRESS
```

## Game Flow

### 1. Deployment Phase
```typescript
// Players commit positions (hidden from opponent)
const commitment = await computePoseidonHash(x, y, salt);
hub.commit_position(playerAddress, commitment);
```

### 2. Movement Phase
```typescript
// Player generates movement proof
const { proof, publicInputs } = await generateMovementProof({
  oldX, oldY, newX, newY, salt,
  oldHash, newHash, turnCounter
});

// Submit to hub
hub.move_unit(playerAddress, proof, publicInputs);
// - Validates turn order
// - Validates proof via verifier contract
// - Updates commitment
// - Increments turn counter
```

### 3. Attack Phase
```typescript
// Defender generates attack proof
const { proof, publicInputs, hit } = await generateAttackProof({
  x, y, salt,
  targetX, targetY,
  commitment, turnCounter
});

// Attacker submits
hub.attack(attackerAddress, proof, publicInputs);
// - Validates turn order
// - Validates proof via verifier contract
// - If hit: decrements HP
// - If HP == 0: game over
```

## Troubleshooting

### "Invalid turn counter"
- Proof was generated with old turn counter
- Regenerate proof with current turn counter from hub

### "Old hash does not match stored commitment"
- Proof uses incorrect old_hash
- Ensure commitment was committed before move
- Use the stored commitment as old_hash

### "Not player's turn"
- Turn order is strictly enforced
- Check whose turn it is with `get_turn()`
- Wait for your turn or opponent's turn to complete

### "Invalid proof"
- Verifier rejected the proof
- Check proof format (UltraHonk, not Groth16)
- Verify public inputs match circuit expectations
