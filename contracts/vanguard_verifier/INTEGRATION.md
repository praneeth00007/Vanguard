# Verifier Integration Guide

This document explains how to use the Vanguard verifier contract with Noir UltraHonk proofs.

## Overview

The verifier contract is a **minimal wrapper** around the official `ultrahonk-rust-verifier` library for Soroban. It accepts proof bytes + public inputs, verifies using the embedded verification key (`vk.bin`), and returns a boolean.

- ✅ No custom cryptography
- ✅ No game logic
- ✅ Uses Soroban BN254 host functions via ultrahonk-rust-verifier

## Verification Flow

```
Frontend (noir_js) -> proof + public inputs
Hub contract -> calls verifier
Verifier -> ultrahonk-rust-verifier -> bool
```

## Contract Interface

```rust
verify_ultrahonk(proof: Bytes, public_inputs: Vec<Bytes>) -> bool
```

- `proof`: UltraHonk proof bytes from Noir
- `public_inputs`: Vec of 32-byte field elements (little-endian)
- Returns: `true` if valid, `false` otherwise

## Verification Key

The contract embeds the verification key at build time:

```
contracts/vanguard_verifier/vk.bin
```

Replace `vk.bin` with the verification key generated by Noir for the circuit you are verifying.

## Public Input Encoding

Each public input must be encoded as a **32-byte, little-endian field element**. The verifier will reject inputs that are not 32 bytes.

## Example Usage (Hub Contract)

```rust
let verifier = VanguardVerifierContractClient::new(&env, &verifier_address);
let is_valid = verifier.verify_ultrahonk(&proof, &public_inputs);

if !is_valid {
    panic!("Invalid proof");
}
```

## Build

```bash
cd contracts/vanguard_verifier
stellar contract build
```

## Notes

- The verifier does not store state.
- Replay protection and game rules are enforced in the hub contract.
- If the proof or public inputs are malformed, the verifier returns `false`.
