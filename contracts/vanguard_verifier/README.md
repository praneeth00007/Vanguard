# Vanguard Verifier Contract

Minimal Soroban contract for verifying Noir UltraHonk proofs.

## Purpose

This contract wraps the official Noir UltraHonk verifier for use in Vanguard's Blindside game. It provides a clean, simple interface for on-chain proof verification.

**This contract does ONE thing**: verify ZK proofs.

**This contract does NOT**:
- Implement game logic
- Store game state
- Manage players or turns
- Handle commitments

## Architecture

```
Frontend (Web Worker)
  ↓ Generate proof using @noir-lang/noir_js
  ↓
Vanguard Hub Contract
  ↓ Call verifier with proof + public inputs
  ↓
Vanguard Verifier Contract  ← YOU ARE HERE
  ↓ Delegate to ultrahonk-rust-verifier
  ↓ Uses Soroban BN254 host functions
  ↓
Return: bool (valid/invalid)
```

## Functions

### `verify_ultrahonk(proof: Bytes, public_inputs: Vec<Bytes>) -> Result<bool, Error>`

Main verification function.

**Parameters:**
- `proof`: UltraHonk proof bytes generated by Noir
- `public_inputs`: Vector of public input field elements (32 bytes each)

**Returns:**
- `Ok(true)` if proof is valid
- `Ok(false)` if proof is invalid
- `Err(Error)` if inputs are malformed

**Example:**
```rust
let is_valid = verifier.verify_ultrahonk(&proof, &public_inputs)?;
if is_valid {
    // Proof verified, update game state
}
```

### `verify_with_stored_vk(vk_id: Bytes, proof: Bytes, public_inputs: Vec<Bytes>) -> Result<bool, Error>`

Verify using a pre-stored verification key.

Useful when the same VK is used for many proofs (like in Vanguard's Blindside where all movement proofs use the same circuit).

**Parameters:**
- `vk_id`: Identifier for the stored VK
- `proof`: UltraHonk proof bytes
- `public_inputs`: Vector of public input field elements

**Returns:**
- `Ok(true)` if proof is valid
- `Ok(false)` if proof is invalid

### `store_vk(vk_id: Bytes, vk_data: Bytes) -> Result<(), Error>`

Store a verification key for reuse.

**Parameters:**
- `vk_id`: Identifier to assign to this VK
- `vk_data`: The verification key data

**Returns:**
- `Ok(())` on success

## Integration with ultrahonk-rust-verifier

This contract is designed to wrap the official `ultrahonk-rust-verifier` library once it's available as a Soroban-compatible dependency.

### Integration Steps

When `ultrahonk-rust-verifier` is available:

1. **Add dependency** to `Cargo.toml`:
   ```toml
   [dependencies]
   ultrahonk-rust-verifier = { git = "https://github.com/yugocabrio/ultrahonk-rust-verifier", features = ["soroban"] }
   ```

2. **Replace stub** in `verify_ultrahonk()`:
   ```rust
   use ultrahonk_rust_verifier::{verify, VerificationKey, Proof};

   // Convert proof bytes
   let proof_data = bytes_to_vec(&proof);
   let proof_obj = Proof::from_bytes(&proof_data)
       .map_err(|_| Error::InvalidProof)?;

   // Convert public inputs
   let public_inputs_vec: Vec<Vec<u8>> = public_inputs
       .iter()
       .map(|b| bytes_to_vec(&b))
       .collect();

   // Get verification key
   let vk = get_or_construct_vk(&env)?;

   // Verify proof (uses Soroban BN254 host functions internally)
   let is_valid = verify(&vk, &proof_obj, &public_inputs_vec)
       .map_err(|_| Error::VerificationFailed)?;

   Ok(is_valid)
   ```

3. **Test** with actual Noir proofs from the circuits

## BN254 Host Functions

The verifier uses Soroban's native BN254 operations through the `ultrahonk-rust-verifier` library. These include:

- **G1 operations**: `g1_add`, `g1_mul`, `g1_msm`
- **G2 operations**: `g2_add`, `g2_mul`
- **Pairing**: `pairing_check`
- **Field operations**: modular arithmetic on BN254 base and scalar fields

These are provided by Soroban Protocol 25+ as native host functions, ensuring efficient on-chain verification.

## Error Handling

```rust
pub enum Error {
    VerificationFailed = 1,   // Proof verification failed
    InvalidProof = 2,          // Malformed proof data
    InvalidPublicInputs = 3,   // Invalid public input format
}
```

**Usage in hub contract:**
```rust
match verifier.verify_ultrahonk(&proof, &public_inputs) {
    Ok(true) => {
        // Proof valid, proceed with game logic
    }
    Ok(false) => {
        // Proof invalid, reject move
        return Err(HubError::InvalidProof);
    }
    Err(e) => {
        // Malformed inputs
        return Err(HubError::VerifierError);
    }
}
```

## Security Considerations

### ✅ What This Contract Does Right

1. **No Custom Crypto**: Uses official ultrahonk-rust-verifier
2. **No Pairing Math**: Delegates to Soroban host functions
3. **No Game Logic**: Pure verification only
4. **Minimal Interface**: Simple, hard to misuse

### ⚠️ Important Notes

1. **Stub Implementation**: Current code is placeholder
2. **Production Requirement**: MUST integrate actual verifier
3. **VK Management**: Consider storing VKs to reduce tx size
4. **Gas Costs**: UltraHonk verification is expensive (~10-50M compute units)

### 🔒 Trust Model

- **Proof Validity**: Guaranteed by UltraHonk soundness
- **BN254 Operations**: Trust Soroban host function implementation
- **Verifier Logic**: Trust ultrahonk-rust-verifier implementation
- **No Trusted Setup**: UltraHonk doesn't require trusted setup

## Performance

Expected costs per verification:

| Metric | Estimate |

- Batch verifications if possible
- Consider proof aggregation for multiple moves
