# Vanguard Verifier Contract

Minimal Soroban contract for verifying Noir UltraHonk proofs.

## Purpose

This contract wraps the official Noir UltraHonk verifier for use in Vanguard's Blindside game. It provides a clean, simple interface for on-chain proof verification.

**This contract does ONE thing**: verify ZK proofs.

**This contract does NOT**:
- Implement game logic
- Store game state
- Manage players or turns
- Handle commitments

## Architecture

```
Frontend (Web Worker)
  ↓ Generate proof using @noir-lang/noir_js
  ↓
Vanguard Hub Contract
  ↓ Call verifier with proof + public inputs
  ↓
Vanguard Verifier Contract  ← YOU ARE HERE
  ↓ Delegate to ultrahonk-rust-verifier
  ↓ Uses Soroban BN254 host functions
  ↓
Return: bool (valid/invalid)
```

## Functions

### `verify_ultrahonk(proof: Bytes, public_inputs: Vec<Bytes>) -> bool`

Main verification function.

**Parameters:**
- `proof`: UltraHonk proof bytes generated by Noir
- `public_inputs`: Vector of public input field elements (32 bytes each)

**Returns:**
- `true` if proof is valid
- `false` if proof is invalid or malformed

**Example:**
```rust
let is_valid = verifier.verify_ultrahonk(&proof, &public_inputs);
if is_valid {
    // Proof verified, update game state
}
```

## Integration with ultrahonk-rust-verifier

This contract directly wraps the official `ultrahonk-rust-verifier` library with Soroban BN254 host functions enabled.

### Verification Key

The verifier expects a `vk.bin` file at `contracts/vanguard_verifier/vk.bin`.
Replace it with the verification key bytes generated by Noir for the circuit you want to verify.

## BN254 Host Functions

The verifier uses Soroban's native BN254 operations through the `ultrahonk-rust-verifier` library. These include:

- **G1 operations**: `g1_add`, `g1_mul`, `g1_msm`
- **G2 operations**: `g2_add`, `g2_mul`
- **Pairing**: `pairing_check`
- **Field operations**: modular arithmetic on BN254 base and scalar fields

These are provided by Soroban Protocol 25+ as native host functions, ensuring efficient on-chain verification.

## Usage from Hub Contract

```rust
use soroban_sdk::{Bytes, Vec, Address};

// In hub contract
let verifier_address = Address::from_string(&"VERIFIER_CONTRACT_ID");
let verifier: VanguardVerifierContractClient = VanguardVerifierContractClient::new(&env, &verifier_address);

// Verify movement proof
let is_valid = verifier.verify_ultrahonk(&proof, &public_inputs)?;

if is_valid {
    // Update game state
    self.update_position(player, new_commitment);
} else {
    return Err(Error::InvalidProof);
}
```

## Security Considerations

### ✅ What This Contract Does Right

1. **No Custom Crypto**: Uses official ultrahonk-rust-verifier
2. **No Pairing Math**: Delegates to Soroban host functions
3. **No Game Logic**: Pure verification only
4. **Minimal Interface**: Simple, hard to misuse

### ⚠️ Important Notes

1. **Stub Implementation**: Current code is placeholder
2. **Production Requirement**: MUST integrate actual verifier
3. **VK Management**: Consider storing VKs to reduce tx size
4. **Gas Costs**: UltraHonk verification is expensive (~10-50M compute units)

### 🔒 Trust Model

- **Proof Validity**: Guaranteed by UltraHonk soundness
- **BN254 Operations**: Trust Soroban host function implementation
- **Verifier Logic**: Trust ultrahonk-rust-verifier implementation
- **No Trusted Setup**: UltraHonk doesn't require trusted setup

## Performance
